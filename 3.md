# Decisions

One entry per decision: what, why. Newest at the bottom. Add an entry only after the decision is agreed.

## Scope and method
1. **Single timestamp only.** Multi-timestamp work is out of scope.
2. **Nested loops.** Completeness is the outer loop, linearisation the inner loop. Each iteration applies the solution to the grid model first, then runs the convergence check (spec order).
3. **State.** The original operating point is frozen; the current one is updated. All baselines (taps, redispatch set-points, N-0 and N-X load flows, N-0 and N-X sensitivities) are refreshed every iteration.
4. **Cumulative MILP.** Each solve is built at the current operating point (current load flow, sensitivities, taps), with cumulative up/down variables whose offsets, per-TSO tap limits and bid headroom refer to the original state. Applied taps are integer-rounded. Curative actions are re-optimised in every solve and never applied to the grid model.
5. **RA count.** The RA-count binary is linked one-sidedly to the cumulative net volume, big-M is the bid's own availability.

## Convergence
6. **Criteria (OR):** (1) the sums of |tap change| and of |MW change| below `max_change_ra_sum_threshold`; (3) the maxima below `max_change_ra`; (4) the sum of overload changes (A, from AC currents; N-0 secured and scanned branches, N-X PATL and TATL pairs) below `max_change_overload`, not evaluated when the N-X refresh failed. The iteration cap is a hard limit.
7. **Cycle exit.** If a solution repeats an earlier one, the member with the lowest total AC overload is kept (ties: lowest cost, latest member). Status `CYCLIC_REPETITION`. The original state is not a candidate. The cycle check runs only when no criterion holds.
8. **Load-flow failure.** An incremental-apply fallback (`incremental_ac_fallback_max_steps`) is tried first. If it fails: at iteration 1 revert to the original state, later to the last converged state.
9. **Not built:** the spec's sum-of-RA-change criterion (eq. 3.35) as a separate criterion; taps and MW share one threshold.

## Load flow and sensitivities
10. **One set of load-flow parameters everywhere** (`build_loadflow_parameters`). Sensitivities previously used pypowsybl defaults and were inconsistent with the load flow.
11. **Contingency propagation is off everywhere.** With it on, the security analysis tripped extra equipment (through node-breaker topology) that the sensitivity analysis does not trip. Switching it off brought the model-versus-AC gap in the N-X final state from 1.98 pp to 0.002 pp on the mock case. Confirmed against a direct load flow (difference ≤ 4.3e-3) for a generator, two shunts and a load contingency. Not reproduced for a busbar contingency and six generic ones: see ASSUMPTIONS.
12. **Sensitivity guard.** Sensitivities are compared with the load flow at the same state (N-0 relative tolerance 1e-3, N-X 1e-2, floors 1 A). On failure the last valid set is reused; with no valid set the run ends with `SENSITIVITY_INVALID`.
13. **N-X sensitivity refresh has no warm start** (the N-0 refresh has, `PREVIOUS_VALUES`). Measured: no effect on the results (differences ≤ 1e-6 relative). Leave as is.

## Input data
14. **TATL.** If a secured branch has no TATL at all, TATL = PATL and TATL duration = 600 s (deliberate deviation from the spec, which says no TATL is considered). A branch side with several TATLs keeps the one with the longest duration (176). A TATL below the PATL is raised to the PATL and keeps its own duration.
15. **Assessed element classification.** An assessed element is secured, scanned or excluded. Neither a secured nor a scanned region code, and no exclusion reason: excluded (reason "no secured or scanned region code"), logged, not optimised. Both codes and no exclusion reason: secured. Only a scanned code and no exclusion reason: **secured** (the Jotunheim data uses it this way; scanned would leave no secured branch). An invalid exclusion reason cancels the RAO (spec).
16. **Redispatch Pmax/Pmin default 0.0** when missing (the unit is then fixed). A warning names every such unit.
17. **PATL ≤ 0 or missing current:** the branch or pair is excluded with a warning, on the N-0 and the N-X side alike.
18. **PST with an empty tap range** is dropped from the model. Group equality pairs that name a dropped PST are dropped with a warning; the remaining members stay tied.
19. **Config.** The default file lists every key (documented defaults). A missing key raises `ConfigKeyError`. Range checks run at import (9 threshold keys ≥ 0, 3 iteration caps ≥ 1); tap-limit keys are validated separately.

## Model gaps (known, not built)
21. Busbar contingency modelling is not settled.

## Stops, missing data, fixed parameters
22. **Result files describe only what was applied.** A stop without a new applied solution (load-flow failure, sensitivity guard, non-optimal solve) reports the last applied solution of the whole run. With nothing applied, PST and RD files show zero change from the original network, curative files show no activation, the summary objective is blank and the status keeps the reason. Why: a rejected solution must never look like a result.
23. **Non-optimal solve.** An infeasible or other non-optimal solve inside the loop ends the run with status `SOLVER_NON_OPTIMAL` and the last applied state, and all result files are written; `scanned_element_constraint_hard` stays `true`. Why: earlier applied work is not lost and the cause is visible.
24. **Cycle exit re-application.** If re-applying both the selected and the newest member fails, the newest member's set-points and voltage snapshot are restored and the loop ends with `REVERTED_TO_LAST_CONVERGED_STATE`. Why: the network must stay at a known converged state.
25. **Empty generator read-back.** An empty `target_p` read-back before a solution is applied stops the loop with the revert status, before anything is applied. Why: a failed load flow could not be reverted.
26. **Missing N-0 current** (missing `i1`/`i2`) is NaN with a warning, so decision 17's exclusion applies. **A NaN or unreadable N-0 sensitivity** excludes the branch from the N-0 constraints with a warning per branch (the N-X pair rule). Why: no silent 0.
27. **PST remedial action without `penaltyFactor`:** 1.0 with a warning (as for RD, which now also warns). Why: 0 made PST moves free.
28. **Bid price:** the price at the run's timestamp; a missing price is `bids.default_price_eur_per_mwh`, a negative price is 0, one summary warning per file. Every bid price is a cost (no sign change by direction, no revenue). Why: a negative cost would let the optimiser activate bids without any overload.
29. **N-X scanned limit** = max(PATL, original N-0 current), the same effective limit as on the N-0 side. Why: one limit per scanned branch, anchored to the original network.
30. **Fixed parameters, not in config** (`run_pipeline.py`): `START_HOUR` ("1030Z"), `N_TIMESTAMPS` (4), `RAART` (None), the per-TSO penalty overrides `PENALTY_REFERENCE_PST_PRA_PER_TSO` / `PENALTY_REFERENCE_RD_PRA_PER_TSO` (None) and `ACTIVATE_CRA_XNE_LINKAGE` (False). Why: not needed for the single-timestamp scope yet.

## Recorded from code comments
32. **`use_reactive_limits` defaults to false**, unlike the spec's `respectReactivePowerLimits=true`. Why: with reactive limits enforced most contingency load flows of the dataset do not converge (several generators need far more reactive power than their limits).
33. **PST group kind** (`blockedGroup` / `reducedGroup`) is not in the data: config `curative_ra.pst_group_kind_default` (`blockedGroup`) plus the per-TSO map `curative_ra.pst_group_kind_per_tso`. Why: the NCP profiles carry no group kind.
34. **PATL source order:** SHS `CurrentLimitTimePoint`, then the AE profile's `BaseCaseCurrentLimit.normalValue`, then the CGM static permanent limit, then 0 with a warning (decision 17 then excludes the branch). Falling back to the CGM value is logged. Why: the NCP is the priority source.
35. **TSO names** come from the Organisation profile (`Org-NineRealms_CD.xml`), not from the EQ `SubGeographicalRegion` (which gives 14 sub-regions instead of 7 TSOs on this dataset).
36. **Incremental AC fallback** (decision 8) needs `component_mode` `MAIN_SYNCHRONOUS`: small islands have no voltage to warm-start from.
37. **Not built or skipped:** corridor results; the CoMo equipment type bus (pypowsybl buses cannot be disconnected); PSTs on 3-winding transformers (left out of the sensitivities, logged); NCP files of profiles that are not parsed (SSI, CD_OR, ER, PS, RAS, FAP, cross-TSO CO exports) are skipped without a warning. GLSK is read from both routes (bid schedule and shift key strategy).

## Performance
38. **Performance keys:** `performance.lf_thread_count` (1), `solver_time_limit_seconds` and `solver_mip_rel_gap` (null), `outputs.write_sensitivity_csvs` (false). The defaults keep one thread, no time limit, the solver's gap. A solve stopped at the limit ends the run as `SOLVER_NON_OPTIMAL` (decision 23). Why: these decide run time on large networks and must not change results unless chosen.
39. **Equality rule for performance changes.** A performance change is kept only if objective, selected actions, taps, MW and all output files stay identical, shown by a test that compares the new logic with the old (kept in the test) or with stored values. Why: speed must not change results. The builder change that summed only non-zero N-X sensitivities was not kept: the model is identical, but the outputs differed in the last digits.

## Calculation modes and RA types
40. **`ac_single_pass` is a separate calculation mode next to the iterative RAO, not a deviation.** The functional spec describes the iterative workflow (CORNET-12, 13, 16); `calculation_mode` adds further modes beside it and leaves `ac_iterative` unchanged (default). Why: the single pass is a choice of the user, not a different reading of the spec. It is recorded in `Spec_Coverage.md` section 4b, not in the deviation table.
41. **The final check of `ac_single_pass` reports the remaining overloads and adds no pairs.** After the applied solution it runs the N-X analysis at that state and reports overloads against PATL and TATL (N-0 and N-X, with the linearised curative effect). Why: a pass that adds pairs would be a loop.
42. **New status `SINGLE_PASS`** (reason "single pass completed"). The existing status values and names stay. Why: a single pass has no convergence criterion, so it is neither `CONVERGED` nor `MAX_ITERATIONS_REACHED`. A final load flow that does not converge keeps the existing revert behaviour (`REVERTED_NON_CONVERGENT`, original network reported).
43. **`ra_types` replaces `enable_pst_remedial_actions` and `enable_rd_remedial_actions` without alias.** The old keys stop the run with a message that names `ra_types`; the GUI migrates saved settings. A type that is not listed is not parsed and leaves no sensitivity call, MILP block or output file. `countertrade` is rejected as not yet supported; `hvdc` is built. Why: one list extends to further types; two booleans plus an alias would keep two sources of truth.
44. **`incremental_ac_fallback_max_steps` stays active in `ac_single_pass`.** The other iteration caps and the convergence thresholds are ignored (one log line says so). Why: the apply step of the single pass keeps the incremental fallback of decision 8, and the fallback needs its step count.
46. **`dc` is a separate calculation mode:** DC load flow, DC security analysis and sensitivities, one MILP solve, one apply, one final AC check; status `SINGLE_PASS`, the same files as `ac_single_pass` (`milp/dc_pass.py`). Why: the AC modes and their outputs must stay unchanged; a flag in `run_single_pass` would put DC branches in the AC path.
47. **DC currents come from one formula and one set of factors:** I = f(vl) x |P| x 1000 / (sqrt(3) x V_nom,side x pf); the sensitivity is sign(P_ref) x f x dP/dx (`pre_milp/dc_conversion.py`). f is `dc_mode.current_factor_by_nominal_voltage_kv` (default 1.0, by exact nominal kV), the same for flows and sensitivities. The pypowsybl DC current is not used (it cannot apply the factors). Why: one rule cannot drift between flows and sensitivities.
48. **One power-factor key: the existing `dc_power_factor` of `load_flow_config.yaml`.** pypowsybl and the formula read the same value; `dc_mode` has only the factor table. Validated as a number > 0 in `calculation_mode` `dc` (decision 57) and in the load flow GUI (minimum 0.01). Why: two keys with the same name and different roles would have to be kept equal by hand. The comment of the key and the "AC only" header of the file were corrected (comments only).
49. **The initial AC load flow is not run in `dc`; a DC load flow that does not converge stops the run.** Nothing else reads the initial AC state (the DC variant replaces the currents, `target_p` is unchanged), so an AC solve would only be another failure point.
50. **Calculation functions take an optional `dc_converter` (default None = AC path).** `run_pipeline` passes it only in `dc`; there is no separate DC backend object. Why: the matrix read-back, guard, filters and CSV writers are shared, a DC copy would drift.
51. **A final AC load flow that does not converge keeps the DC solution:** the model and the PST/RD rows are those of the solved model, the final-check rows are left out, the status stays `SINGLE_PASS`, the run goes on. `ac_single_pass` reports the original network instead. Why: the DC solution has no AC state to revert to.
52. **Fallback voltages:** a DC load flow leaves bus voltages NaN, so when the direct AC jump fails one extra AC load flow at the unmodified state gives the start voltages of the incremental fallback; the normal path has no extra calculation. `voltage_init_mode` PREVIOUS_VALUES becomes UNIFORM_VALUES for the first AC load flow of the DC mode.
53. **Scanned limits in `dc` use the DC-converted initial current, and the final AC check reuses them.** The effective limit of a scanned element is max(PATL, initial loading); in `dc` the initial loading is the DC current, in the model and in the check. Why: the check must judge the model's own constraint.
54. **DC-only summary rows and no change to CSV shapes.** `dc_power_factor`, `dc_voltage_levels_with_factor`, `final_check_basis` (= ac), `final_check_evaluated`, `final_check_reason` (on failure), `lf_basecase_basis` and `original_network_currents_basis` (= dc) are written in `dc` only; the AC summaries are unchanged. No header comment and no new column in any CSV (a comment line breaks CSV readers, a column changes the AC file shapes). Why: D8.3.
55. **Sensitivity guard in `dc`: the N-X deviation check uses 5 % instead of 1 %** (`sensitivity_checks.DC_NX_RELATIVE_TOLERANCE`; the AC modes keep 1 %). The DC security and sensitivity analyses distribute the slack differently after a contingency that disconnects generation or load. The missing-reference, zero-reference and all-zero checks and the N-0 guard stay as in AC. Why: with 1 % the DC mode stops on a normal case.
56. **GUI: the DC factor table is read from the active `rao_config.yaml` and never stored in the saved GUI settings.** Why: it is edited in the config file only; a copy would hide later edits.
57. **`dc_mode` and `dc_power_factor` are checked only in `calculation_mode` `dc`.** In the other modes a missing `dc_mode` section is the default table (every factor 1.0). Why: the AC modes do not use either value; checking them stopped older configs that worked.
58. **A saved GUI `dc_power_factor` that is not a number > 0 becomes 1.0, with a note on every page.** The load flow page accepted 0.0 before (minimum 0.0); with its minimum now 0.01 such a saved value made the page raise and the runs stop. `load_settings` replaces it with the default 1.0 and returns a note the pages show as a warning; saving the load flow settings keeps the new value. Why: a recoverable old setting must not block the GUI.
59. **Text files are UTF-8 without BOM, named through one constant** `src/rao/text_encoding.TEXT_ENCODING`, passed at every text read and write of the pipeline, its GUI and the tests (result CSVs, run log, YAML configs, GUI settings, the pipeline's console output). The GUI loads the constant by file path. A config file that is not valid UTF-8 stops the run naming the file; input XML keeps its parser's own handling. `tests/test_rao_text_encoding.py` fails on a text-file call in `src/` without an encoding. Why: the platform default on Windows is cp1252, which broke names outside it; one constant keeps the rule in one place.

## HVDC remedial actions
60. **An HVDC link is two generating-like units on EquivalentInjections, balanced in a group.** An HVDC RA is a `GridStateAlterationRemedialAction` with one `EquivalentInjectionAction`; its two units sit in a `balanced` `RemedialActionGroup`. Per unit two continuous variables dP+ and dP- (no binaries); the group balance is dg1 + dg2 = 0; the units are not in the N-0 RD balance; losses are not modelled (the mismatch shows in the final AC check). A description other than "HVDC..." on the EI is only a warning. Why: the CGM has one station per link, so the pair of EIs is what the network model offers.
61. **Range of a unit: the most restrictive range wins, technical limits cap it, a side without a bound is an error.** Most restrictive = lowest maximum and highest minimum. EI minP/maxP are injection sign as pypowsybl passes them and are used as given (pinned by a test). Absolute values are literal; incremental values are magnitudes added to or subtracted from the original P0; `upAndDown` with one value v is symmetric. Technical limits of 1e300 or more count as none, and a unit without technical limits logs a warning. Why: an unbounded unit would be unlimited.
62. **Cost: `penaltyFactor` x reference x |change|; factor 0 is free.** `penalty_costs.penalty_reference_hvdc_pra` / `_cra` (EUR/MW, default 100, read only with `hvdc` in `ra_types`); a missing `penaltyFactor` is 1.0 with a warning (decision 108). At factor 0 the pair may end at the edge of its range at no cost; use a small factor above 0 to limit it. Preventive cost = sum of both units' factor x PRA reference x |cumulative change|; curative cost = factor x CRA reference x the maximum over contingencies of (dPc+ + dPc-). The objective equals the sum of the reported terms.
63. **Curative HVDC: exact bound per contingency, atomic group, outside the RD balances.** Variables dPc+/dPc- per (unit, contingency) exist when the RA is linked, the reaction time fits the branch's TATL duration (both units must be available), the EI is not an outage element and its N-X sensitivities are not all zero; a failing unit takes its partner with it. Bound per contingency: Pmin_op <= P + preventive change + curative change <= Pmax_op (a curative RA without its own range uses the preventive range of the EI); balance dPc_g1 + dPc_g2 = 0 per (group, contingency). The curative effect is in the N-X PATL and scanned rows of its own contingency, not in the TATL row. Curative actions are re-optimised every solve, never written to the network, and need N-X analysis. Why: the preventive and the curative change act on one set point.
64. **Guards: solved network, silent zero, one preventive unit per EI.** pypowsybl returns 0 for an injection outside the solved synchronous component, so both units must be in the solved main network and a unit whose N-0 sensitivities are all 0 is an error; all-zero N-X sensitivities in a contingency make the group unavailable there. A group with an HVDC unit needs exactly two HVDC units and no other RA; a unit without a group or in two groups, a group mixing preventive and curative, the same EI twice, two preventive units on one EI, an EI that is also an RD unit, or an RA with two EI actions are errors. Why: a silently ineffective or half-modelled link must never look like a result.
65. **Write-back and loops share the RD path.** Preventive set points travel in the RD `target_p` dictionary (apply, restore, fallback ramp, cycle snapshots). HVDC sensitivities are refreshed with the RD ones in `ac_iterative`, read once in `ac_single_pass`, and come from the DC analysis in `dc`. HVDC MW counts in the RD change sums and in convergence criteria 1 and 3. Why: the movement of a set point is a movement of the operating point.
66. **The post-contingency result of a curative HVDC action is the MILP prediction.** Curative actions are never applied, so the post-PRA+CRA loadings are the AC N-X current of the applied state plus the linearised curative effect, and the final check adds the same effect. HVDC link contingencies are not modelled: a contingency removes an HVDC unit only when its EI is an outage element. Set points are floats and applied unrounded.
67. **The dependency predicate fix is an exception to "outputs without `hvdc` are identical".** The group parser accepts both predicate names for balanced and restrictive groups. A hard scanned-element N-0 row that no remedial action touches (constant left side) now builds instead of stopping Pyomo (needed for curative-only HVDC; the effective limit is at least the original loading).
68. **A CGM set point outside its resolved range widens the range to include it.** If P0 lies outside [Pmin_op, Pmax_op] the bound on that side becomes P0, with a warning naming the unit; an empty range stays an error. Why: the bounds are hard constraints; with P0 outside them the model would have to move the pair without any overload or be infeasible.
69. **A countertrade (CT) RA is a bid per bidding zone, modelled as an RD bid.** Each CT RA becomes one `RDUnit` (`countertrade=True`) per movable unit of its zone, its bids join `bid_list` and the weights travel per bid, so the RD machinery is reused (bid variables, net injection, global balance, curative variables, group caps, RA count). Why: the functional spec describes CT as the RD bid of a zone and the up and down weights of one RA differ, which a glsk per RA cannot hold. CT works without `rd` in `ra_types`. Open gap: the CT parser never fills `linked_xne_mrids`; it matters only if `ACTIVATE_CRA_XNE_LINKAGE` (hard-coded False) is enabled.
70. **Only `proportionalForRemainingCapacity` is implemented.** A CT RA without a strategy is read with it assumed (decision 107); other values, or different values on the RA and its bids, ignore the RA with a warning. The predicates `nc:CountertradeRemedialAction.gLSKStrategy` and `nc:PowerBidSchedule.gLSKStrategy` are an implementation choice, unconfirmed against the profile.
71. **The CT weights are direction-aware, computed once from the original set points and identical everywhere.** Up: (Pmax - PROD) / sum, down: (PROD - Pmin) / sum, normalised after the exclusion; the same in every mode, iteration, preventive and curative, never from the actions of a solve. Why: no bilinear terms; the final AC check shows the effect of the approximation; the footroom form for down gives a unit at Pmax a share in a down bid.
72. **Which units take part in CT.** A unit of the zone's control area(s) that is a generator (no EquivalentInjection or external grid), connected, in the main synchronous component, with bounded limits, on by the F2 rule, with PROD not above Pmax, and with room in the direction. 0 < PROD < Pmin gives Pmin := PROD; a negative Pmin is accepted. Generators without a unit id or in no control area are dropped with one log line; an empty direction fixes that bid to volume 0 (one warning). Why: CT can neither start nor stop a unit.
73. **Balance, limits and on/off rows of CT.** The CT injections are in the global N-0 balance and the per-contingency balance with RD. Pmin/Pmax are hard rows on the combined RD + CT total: preventive per unit, curative per unit over the maxima of all contingencies (decision 130). A unit with an on/off binary gets one-sided CT rows (at most Pmax x u); CT bids do not count in the start-up test, and CT-only units get a status (Pmin := PROD). Why: a unit that RD shuts down must not receive CT volume, and CT must never change a unit's status.
74. **CT cost.** Preventive: penaltyFactor x `penalty_reference_ct_pra` x volume, bid price x volume, activation cost with a binary. Curative: penaltyFactor x `penalty_reference_ct_cra` x the maximum over contingencies plus the reservation price (reservePrice, else the energy price) x the maximum. A missing penaltyFactor is 1.0 with a log line. Each part is a named objective term, so the objective equals the sum of the reported terms. Both references default to the RD preventive reference.
75. **CT counts in the RA-count limits and in restrictive RA groups.** Both read `bid.ra_mrid`, which stays the real CT RA. Bid dependencies (restrictive/inclusive between bids) are not implemented for RD, so not for CT. Why: the limits are shared limits (CORNET-4838, maxNumRA).
76. **The RD result files stay RD-only.** `results_preventive_rd.csv`, `results_generating_units.csv` (the RD part of the unit total), `results_curative_rd.csv`, `results_preventive_rd_ra_count.csv`, `results_preventive_rd_ra_groups.csv`, `results_lead_times.csv` and `rd_cra_availability.csv` contain no CT bid; the RA-count and group limits themselves still count CT. Why: the CT numbers have their own files and summary rows; mixing them would hide what each type did.
77. **CT outputs exist only with `countertrade` in `ra_types` and a usable CT RA:** the CT results, the curative CT results, the CT availability and the zone net positions and exchanges (the exchange before and after from the same kind of load flow: AC in the AC modes, DC in `dc`; the two halves of a tie are paired by element name and opposite flow, a tie without a partner is skipped with a log line); the summary carries the CT volumes and costs. Why: the CGM interchange values do not match their targets, so they are not used.
78. **Developed and tested on a generated mock.** `tests/mock_builders/ct_mock.py` builds the NCP from `NCP_pst_fallback_scenario.zip` (CT RAs and bids for Belgovia and Galia, a PATL for the Belgovia half of TieLine_GA_BO4, a contingency that trips TieLine_GA_BO5 for the curative case, variants for strategies, zones, volumes, penalty factors, groups); the fixture CT RA is used only for one negative test. Why: the input data has no valid CT data; no real CT data is assumed.
79. **The generating unit file in a run with countertrade shows the true dispatch with RD and CT apart.** `result_production_mw` is the final dispatch (initial + RD + CT), the RD columns hold the RD part only and `ct_volume_net_mw` the CT part, both summed from the cumulative bid volumes. Without countertrade the file is unchanged. Why: the file must show what the unit produces without counting CT as RD.
80. **CT-only units in the generating unit file.** Every CT unit (non-zero weight in at least one direction) that is in no RD glsk gets its own row after the RD units: RD columns 0, `ct_volume_net_mw` its CT part, `result_production_mw` initial + CT, the TSO of its CT RA. Why: the file shows the dispatch of every unit an RA moves.

## NCP input handling and the NCP test dataset
81. **A zero or unreadable `GridStateAlteration.timePerStage` is left unset, with a warning.** `parse_psts` names the PST and its remedial action and treats the value as missing (`PT0S`, text, years or months); the curative PST then gets no CRA availability, as with any missing timing attribute (no default). `compute_pst_cra_availability` also skips a PST whose time per stage is 0 or less. Why: the value divides the TATL window into tap stages; before, a division by zero stopped the run.
82. **A contingency link or bid that refers to no RA is named in a warning; matching is unchanged.** `warn_unmatched_ra_references` (per TSO) warns once per `ContingencyWithRemedialAction` and per `PowerBidSchedule` whose RA reference matches no RA of the TSO's RA file, naming the object and the mRID. Typical cause: an RA whose `rdf:ID` differs from its mRID. Why: the loss was silent.
83. **PST range direction is intended; the NCP test dataset is generated.** In `build_pst_tap_bounds_curative` `up` and `upAndDown` set the upper bound and `down` the lower bound. The NCP test dataset (`tests/mock_builders/ncp_dataset.py`) is mock data built by a generator on `tests/fixtures/CGM_package.zip` with data rules the generator asserts; the TATL is CGM data, so the TATL rows are checked on the CGM values.
84. **A curative PST range with its lower bound above its upper bound is ignored, with a warning.** `build_pst_tap_bounds_curative` warns naming the PST and both bounds and gives no entry, so the PST's operating range is used; `lower == upper` is valid (the PST is fixed at that tap). Why: no tap position fits an empty range, and Pyomo refused to build the row.

## NCP standard form
85. **Target profiles: RemedialAction 2.5 and StateInstructionSchedule 2.5; sample G (`NCP_generic.zip`, 2.4) stays legacy and is not changed.** Standard form = the ENTSO-E ReliCapGrid 2.5 files; where an old sample and the PDFs disagree the official 2.5 files decide (see `docs/specs/ncp_data_requirements.md`). Why: the mock may be wrong.
86. **Standard form is read first; the old mock form stays as a fallback with a deprecation warning once per file.** Both present: the standard form wins, with a warning. Why: tests and data migrate one part at a time.
87. **The old-form code is removed in the next release.**
88. **Redispatch units are derived from the shift key chain (GLSK) of the RedispatchRemedialAction, not from `RotatingMachineAction`.** `RotatingMachineAction` (and its ramp attributes, which the profile does not have) is old form only.
89. **A `PowerShiftKeySchedule` resource that is not a `GeneratingUnit` is not read: it is dropped with a warning that counts the dropped schedules.** Applies to the shift key schedules of the SIS only; HVDC (EquivalentInjectionAction in the RA profile) is unaffected.
90. **A countertrade RA without a strategy defaults to `proportionalForRemainingCapacity`.** This is an assumption: neither profile has a strategy kind (ASSUMPTIONS).
91. **`maxEconomicPMargin` and `minEconomicPMargin` are not read** until OPEN-27 is answered.

142. **Zero-sensitivity terms are left out of the N-X rows when N-X pruning is on.** `NxMilpInputs.drop_zero_pst_terms` / `drop_zero_rd_terms` (default False; `run_pipeline` sets them when `sensitivity_threshold_pct_pst_nx` or `_rd_nx` is above 0): the PST and RD terms are built only for the pairs whose sensitivity is not zero. 143. **Assessed-element switches of the AssessedElement profile specification.** `isCombinableWithContingency=false` is applied: `included_contingencies` becomes the tuple of the `included` links (empty = after no contingency; None = all), `excluded` still wins, the N state follows `inBaseCase` only. 169. **Countertrade sensitivity per RA and direction.** sens_ct(branch, state, RA, direction) = sum over the units of weight x sens(branch, unit) is one sensitivity variable per countertrade RA and direction (`ct_sensitivity`; N-0 and N-X, AC and DC; variable id `CT|<RA>|up` / `down`), computed from the per-unit sensitivities and summed at once (170). Per-unit rows that do not scale with branches x contingencies stay per unit (injection expression, balance, unit limits, costs). The sensitivity files list the variables of the model, so countertrade-only units appear as one row per RA and direction.
170. **Countertrade sensitivity is computed from per-unit values and aggregated at once** (replaces the zone approach of 169). sens_ct(branch, state, RA, direction) = sum over the units of weight x sens(branch, state, unit), from the per-unit analysis (the parameters, contingencies and DC conversion of the RD units), so it equals the per-unit sum by construction. N-X runs in batches of contingencies (`ct_sensitivity.BATCH_BUDGET` = 3 million values per batch, at least 1 contingency) and sums each contingency right after the read; N-0 is one analysis whose countertrade-only rows are summed and dropped at once. Pruning equals the per-unit formulation: N-X Filter 2 is applied to each unit value before the sum, the later Filter 2 leaves the `CT|` rows alone, the N-0 branch rule uses the maximum over the per-unit values (NaN ignored). A NaN value of a unit makes the sum of every RA and direction that uses it NaN on that branch (the pair is skipped by the model); a unit without a row counts 0. Why: exactness by construction outweighs the time (about 6 times the zone approach, the same as the per-unit run); memory is solved either way.
171. **Elements no official source has are removed from the readers.** Removed: the bid attributes `penaltyFactor`, `minEnergyBid`, `maxEnergyBid`, `stepSizeCTRD` and the `PowerBid` fields they filled; a generator id as the unit of a shift key; the declared-value branch of the countertrade `gLSKStrategy` (the rule stays: any strategy value is ignored with one warning per RA and the RA is kept); the countertrade attributes `powerShiftKey` and `method`; a group limit linked directly from the time point; the plain dependency predicate `RemedialActionDependency.RemedialActionGroup`. Each one found in a file gives one summary warning per file and kind, "not supported, ignored" (`ncp_parser.warn_not_supported`, `tests/test_rao_unsupported_elements.py`). Kept: the `RotatingMachineAction` redispatch form and the `PowerShiftKeyStrategy` route of the official sample, and the defaults (missing `combinationConstraintKind` included, missing interpolation kind none, missing `penaltyFactor` 1.0, direction from the name suffix). The mock builders are in `tests/mock_builders/`; the standard mock without countertrade is the frozen fixture `NCP_mock_standard_base.zip`, the shipped mock is that base plus the countertrade RAs. `tests/test_rao_suite_independence.py` keeps the suite dependent only on `src/`, `tests/` and `tests/fixtures`.
172. **One timestamp: the CGM scenario time.** The run optimises the CGM scenario time and nothing else; time coupling is out of scope. Removed: the timestamp list, the `timestamp_list` / `price_timestamp` parameters of the readers, and the per-timeframe RA-count limit (constraint, slack, penalty, config key `ra_limits.max_ra_count_per_timeframe_tso`). A config that still sets the removed key to a value gets one warning "no longer used, ignored"; null stays silent. Kept: the per-timestamp RA-count limit, the lead-time check at the run timestamp, bid and shift-key time point selection by date and time, TATL durations. The outputs list one timestamp (one row per contingency, one per scanned element).
173. **The NCP files of a profile are one pool; the TSO of an object is its operator in the content.** All files of a profile (AE, CO, RA, SIS, ER, SHS) are read together whatever their header creator or file name; objects link by id across files. The same object id in two files of one profile stops the run with an error naming both files and the id. A profile with no file at all (AE, CO or RA) stops the run. The TSO of an assessed element is `AssessedElement.AssessedSystemOperator`, that of a PST, RD unit, countertrade RA or HVDC unit is `RemedialAction.RemedialActionSystemOperator`; an EIC URI gives its last path segment, a local id is resolved through the Organisation (CD) file; a missing or unresolved operator takes the TSO of the file, with one summary warning per file. The display name of a TSO is its CD name, else its EIC. Everything keyed per TSO (tap limits, RA-count limits, PST group kind, penalty references, inventory, TSO columns) uses the TSO of the object. Code: `pre_milp/operators.py`, `ncp_loader.NcpPools`, `ncp_parser.PooledFiles`.

174. **N-X sensitivity CSVs are off by default; the N-X PST threshold applies while the sensitivities are read.** `outputs.write_sensitivity_csvs` is false in both config files (the test helper switches it on). `sensitivity_threshold_pct_pst_nx` drops entries per contingency right after the pypowsybl matrix is read, in every calculation mode and in each refresh; the limit is the PATL of a secured branch and the effective limit of a scanned one. The kept table is copied to a compact array so the full array of the contingency is freed. The CSV, when on, is written one contingency at a time before the threshold, so the file does not depend on it. `ac_single_pass` and `dc` do no refresh of the N-0 sensitivities, so the N-0 refresh thresholds do not apply there. Per-item warnings (CurrentLimit sequence number outside {1,2}, branch reference that is no line or 2W transformer, inBaseCase=false, missing penaltyFactor, N-0 branch without result, non-uniform tap steps, unreadable N-0 sensitivity, AE without region code, bid or link to an unknown RA) are one line per file or TSO with the count and the first 5 ids, the full list at DEBUG. Why: the N-X PST sensitivity (about 10^8 values on a large network) filled the disk.
175. **PST sensitivity thresholds compare the effect per tap.** `sensitivity_threshold_pct_pst` (N-0) and `sensitivity_threshold_pct_pst_nx` (N-X) mean percent of the branch limit per tap: an N-X entry is dropped when |A per degree| x |degrees per tap of the PST| < threshold x limit / 100; an N-0 branch is dropped when the largest such value over its PSTs is below it. The degrees per tap are those the MILP uses (`build_pst_degrees_per_tap`); a PST without one is never dropped. Why: the effect a tap has on a branch is what the optimiser can use. The stored sensitivities and CSVs stay in A per degree; the RD and countertrade thresholds stay per MW.

176. **Several TATLs on a branch side keep the one with the longest acceptable duration.** `compute_tatl_data` takes, per monitored secured branch side, the TATL with the longest duration as a pair (value and duration); a side with one TATL is unchanged, a side with none keeps the fallback (PATL, default duration); a TATL below the PATL is raised to the PATL. One INFO line counts the sides with several TATLs. Replaces "no TATL" for such a side (14).

177. **A branch without a reference current is dropped for its pair, not the whole run.** A monitored branch with a load-flow current above 1 A and a NaN or missing reference current in the sensitivity analysis (for example a tie line open at one end) is no longer a guard failure. N-X: the (branch, contingency) pair is left out of `lf_nx` like a branch missing after a network split, with one summary warning; a contingency is invalid for this cause only when none has a branch with a reference current (the run stops). N-0: the branch's entries become NaN, which the model leaves out. Deviation, zero-reference and all-zero failures stay failures.

178. **The sensitivity guard drops deviating pairs below an absolute floor and stops only on coverage.** The two OpenLoadFlow analyses distribute the post-contingency imbalance slightly differently with generation-based slack distribution (gaps of a few ampere on lightly loaded branches); it is not a set-up error. Rules: (1) a pair deviates only when the relative gap exceeds the tolerance (AC 0.01, DC 0.05, N-0 0.001) and the absolute gap exceeds `sensitivity_guard.absolute_floor_ampere` (default 5.0); (2) a deviating pair is dropped for that (branch, contingency) only (N-0: the branch), with one summary warning (pairs, contingencies, maximum and median gap, first 5 ids); (3) a zero reference and all-zero sensitivities keep their behaviour (the contingency is invalid, the last valid set is reused, at the first computation the run stops), with one exception in `calculation_mode` dc, N-X only: a pair whose reference current is exactly 0 while its load-flow current is not, but at most `sensitivity_guard.absolute_floor_ampere`, is kept (it counts as valid) and is reported in one summary warning (pairs, contingencies, first 5 ids); a load-flow current above the floor, a contingency with all sensitivities zero, the AC modes and N-0 keep the failure (the two analyses distribute the slack differently, so a branch that carries almost no current can have a reference of exactly 0 next to a load-flow current of an ampere or two); (4) the run stops when no contingency has valid N-X data, or when the dropped pairs exceed `sensitivity_guard.max_dropped_share` (default 0.01) of all monitored pairs; (5) one INFO coverage line per run; (6) `contingencyPropagation=false` is passed to every sensitivity analysis through the shared builder, the same parameters as the security analysis. The share check runs at the first computation; a refresh drops pairs the same way but does not stop on the share.

179. **A PST on a 3-winding transformer is left out of the PST list once, before every step.** `pre_milp/pst_support.exclude_three_winding_psts` removes such PSTs right after the parsing (both rows of a transformer with a preventive and a curative RA), so the sensitivities, tap bounds, groups, model, apply step, verification and outputs never see them. A PST counts as one when its mRID is not a 2-winding transformer but is a 3-winding transformer or has a phase tap changer; an mRID nowhere in the network is kept. One summary warning; a group loses its excluded members and is dissolved when fewer than 2 remain. Why: the apply step failed on a PST that only the sensitivity filters had left out.

180. **Objective breakdown after every solve (log only).** `milp_builder` keeps every objective term by name (`objective_term_expressions`); `milp/objective_report` writes one INFO block after each solve: the value of each term, the number of PSTs moved, the tap steps and the 5 largest moves, and one line per PST group whose members started on different taps. Rules that move a PST with nothing overloaded: the group equality compares absolute tap positions (members on different taps are forced to a common tap), and a current tap outside the effective bounds is forced back inside. The per-TSO tap cap, the discrete domain and the cumulative offset never force a move; the curative group equality compares tap changes and forces nothing.

181. **Time and memory per step (log only).** `run_profile` marks the steps of a run (setup, CGM load, NCP parsing, outputs setup, scanned elements, N-0 sensitivity, N-X analysis and sensitivity, TATL data, curative preprocessing, MILP build, solve, apply and verification, outputs); a step that comes back is added up. Memory is the RSS of the process at the end of the step and the peak of samples every 0.5 s. The table is logged at the end of the run and also when the run fails. psutil is optional: without it the time is logged with one warning and no memory column.

182. **The N-X limit of a scanned element is per pair.** The limit of a scanned (branch, contingency) pair is `max(PATL, initial post-contingency loading of that pair)`, from the original N-X currents (`NxMilpInputs.lf_nx_original`), same side as the model flow, so with no move the slack is 0. The N-0 scanned row keeps `max(PATL, initial N-0 loading)`. The limit is kept per pair on the model and used by the builder, the final check, `find_new_congested_pairs` and the scanned elements output; the loading pre-filter of scanned pairs uses the same limit. Why: comparing the post-contingency current with an N-0 based limit charged an overload that has nothing to do with the post-contingency flow.

183. **Overload diagnosis after the final check (log only).** After `run_final_check` (single pass and dc), one INFO block per overloaded N-X pair (the 20 largest at INFO, the rest at DEBUG): branch, contingency, limit, AC current, overload, the largest PST effect per tap and the best possible relief within the tap ranges of the preventive PSTs; the line says "pruned" when the PST threshold removed the raw value. The last line says "no PST can relieve this overload by more than X A" when the best relief is below the overload (per-TSO caps and curative PSTs are not part of the relief). No result file changes (`milp/overload_diagnosis.py`).

184. **The solver line counts the overloads by kind (log only).** It shows N-0 overloaded branches (secured and soft scanned), N-X PATL pairs, N-X TATL pairs and N-X scanned pairs with a positive slack. The summary row `remaining_overload_count` covers the N-0 secured branches only (not an overall count); the single-pass and dc summaries carry the per-kind final-check counts.

185. **N-X rows that can never bind are not built (exact model reduction).** For every N-X flow row (PATL, TATL, scanned) an upper bound of |flow| is `|I| + sum |coefficient| x largest change` (PST taps from the current tap to each bound, RD and countertrade volumes from their variable bounds, preventive HVDC from its operating range, curative terms from their bounds). A row whose bound is at most `limit - margin` is left out with its slack variable (`nx_constraint_filter.enabled`, default true; `margin_ampere`, default 1.0). A term without a finite bound (curative HVDC) keeps the row. The check runs at every build. Skipped pairs stay in `model.nx_skipped_pairs` and count as evaluated pairs with slack 0, so every result file is unchanged. One INFO line per build: considered, added, skipped, share.
186. **Default bid price.** A bid with a volume but no price at the run time (no price on its time point, or no time point there) gets `bids.default_price_eur_per_mwh` (a number >= 0, default 0.0), for redispatch and countertrade bids alike. One warning per file gives the count, the price used and the first 5 ids; a bid with no time point at the run time is counted apart (its volume is 0). A negative price is still set to 0.

187. **The N-X redispatch and countertrade threshold is applied per contingency, in percent of the limit per 100 MW.** `thresholds.sensitivity_threshold_pct_rd_nx` is applied as each contingency is read, in every calculation mode: an entry is dropped when `|A per MW| x 100 < threshold x limit / 100`. One key covers redispatch and countertrade; a countertrade unit is judged before its values are summed per RA and direction. One INFO line gives the threshold and the entries kept and dropped. The guard runs after the loop, as for the PSTs.

188. **One id comparison for every bid and shift-key link.** `ncp_parser.id_key` removes a base URI, `#`, `urn:uuid:` and every leading `_` and compares in lower case; an RA answers to its mRID, its rdf:ID and its rdf:about (`reference_lookup`). It is used for the bid to RA link, the bid and strategy to shift-key routes, the unmatched-reference warning and the countertrade checks, and the contingency and assessed-element links of an RA are keyed the same way. The other resource classes stay unsupported; one warning per file counts the shift keys per class.

190. **Why a bid has no generating unit of its GLSK in the model.** In the builder the only ways are: the RA has no GLSK entry, its GLSK is empty after resolution, or none of its GLSK units is in the generator data. The line that said "empty GLSK" per bid is now one summary per cause (bids, RAs, first 5 ids; all at DEBUG). A bid whose RA is not in the RD list is dropped before this check; with the shared id link above the parser gives every bid its RA's own id.

191. **Overload diagnosis with redispatch and countertrade.** Per overloaded N-X pair, two more lines (redispatch, countertrade): the largest effect per 100 MW of a preventive bid and the best possible relief within the bid volumes and the Pmax / Pmin of the units, from the applied volumes ("before the threshold" says pruned when the RD threshold is on); and one closing line naming the best RA type (PST, redispatch or countertrade) and its relief.

192. **Log summaries.** Count plus the first 5 ids, all ids at DEBUG, one line per file or TSO: bid attributes not read, bids without a price or without a time point at the run time, RD and countertrade RAs ignored, participation factors that do not sum to 1, units not connected and excluded, RAs with an empty GLSK, preventive bids blocked by a unit that is off, HVDC and countertrade RAs without a penaltyFactor. 193. **Lead-time decision point.** `lead_time.decision_point_hours_before_run` (default 1.0, number >= 0) is the distance between the decision point and the run time. A bid is usable when its lead time is shorter than that distance (strict: a lead time that ends exactly at the run time blocks the bid; a bid without a lead time is always usable). A decision point on the previous day is handled by the subtraction. It applies to every bid (redispatch and countertrade, preventive and curative); a blocked bid has its volume bounds fixed to 0. One INFO line per run and scope gives the decision point, the count and the first 5 ids. `RAART` (an explicit clock time) still overrides the distance. Why: the distance is an input of the operation, not of the code.

194. **N-X sensitivities run in batches of contingencies.** `nx_sensitivity.contingency_batch_size` (integer >= 1, default 200): the PST, redispatch, countertrade-unit and HVDC analyses run one pypowsybl analysis per batch of contingencies; each batch is read, guarded, filtered, thresholded and released before the next one. The result is the one of a single analysis (same tables in the same order, CSV rows, guard decisions, pairs left out, threshold lines); a batch size at or above the number of contingencies is one analysis. The one guard rule that looks at all contingencies together (no contingency has a valid branch) is applied to the union. One summary line per cause, not per batch. Why: pypowsybl keeps the results of all contingencies of an analysis until it is released, which took hours and tens of GB on a large network.

195. **One shared balance for redispatch and countertrade.** The sum of the redispatch and countertrade volumes is 0, per contingency for the curative ones. No separate balance per RA type. No code change.

207. **The MILP can keep a margin to the limits.** `thresholds.milp_limit_factor_patl`, `_tatl` and `_scanned` (default 1.0, 0 < factor <= 1): in the MILP constraints only, the limit becomes limit x factor (N-0 and N-X PATL; N-X TATL; N-0 and N-X scanned, on the effective limit). The N-X constraint filter takes the same reduced limit, so it never drops a row that can now bind. The final AC check, the output files, the sensitivity thresholds, the overload diagnosis, the convergence check (`overload_monitoring`) and the loading thresholds keep the real limit. Why: the linearisation is not exact; a margin keeps the AC result inside the limit without changing the limits themselves. A scanned factor below 1 with a hard scanned constraint can make the solve infeasible (warning).

208. **The TATL of a side without a CGM TATL is PATL x a factor.** `curative_ra.tatl_fallback_factor` (default 1.0, number >= 1) replaces the fixed TATL = PATL: such a side gets TATL = PATL x factor with the duration `tatl_fallback_duration_s`. With 1.0 nothing changes (TATL = PATL, no TATL constraint); above 1 the side gets a TATL constraint against PATL x factor. A TATL from the CGM, the longest of several, and the raise of a TATL below the PATL are not touched. A side without a PATL still has no entry.

209. **The loadings files show the current of the solved MILP.** `current_milp_a` is the value of the flow expression of the N-0 row (or the N-X PATL or scanned row of the pair) in the solved final model: the model current plus the sensitivities times the RA changes (preventive; for N-X also the curative ones of the contingency). In `ac_iterative` it is the last solve; in `dc` the model current is the DC one. `loading_milp_pct` is relative to the real `limit_a`, not to the limit x factor of the MILP. A row without a MILP constraint (below the loading thresholds of the model, a pair restricted away by the NCP links, a row the constraint filter dropped as never binding) has empty values. The row rule of the files is unchanged. Why: the gap between the MILP current and the AC current after the RAs shows how far the linearisation was off, per row.

210. **Permanent limits are read from inactive limit groups.** When a branch terminal has several limit groups and none is selected, pypowsybl's default `get_operational_limits()` returns none of its limits, so the side had no PATL and its assessed elements were excluded. For a side without a permanent CURRENT limit in the default call, `build_branch_limits` now reads the limits again with `show_inactive_sets=True`: if every group of the side has the same permanent CURRENT value it is the PATL; if the values differ (or a group has none) no value is used (as before) and the side is counted in one summary line (count, max/min ratio range, first 5 ids). The TATLs read by the N-X analysis follow the same rule (used only when all groups have the same TATLs, and only for a side with no TATL in the default call). A side with a selected group is unchanged. Why: a group chosen by us among groups that disagree would be arbitrary; equal groups lose nothing. The golden fixtures have one group per terminal, so no output moves.
